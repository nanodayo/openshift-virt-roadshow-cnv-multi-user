=  仮想マシンとアプリケーションの操作

== はじめに

本ラボのこのセクションは、OpenShift Virtualization 環境で仮想マシンを操作する際に多くの管理者が必要とする Day-2 運用に焦点を当てています。本ロードショー全体で培った OpenShift 環境における VM の動作の理解を活用し、このセクションのタスクを完了します。本ケースでは、本ロードショーの前半で VMware vSphere からインポートした 3 台の仮想マシンを操作し、OpenShift Virtualization 上で実行されるようになったサーバー上のアプリケーションにアクセスできるよう、いくつかの軽微な設定変更を行います。これを実現するため、OpenShift SDN ポッドネットワークを利用する際のデフォルトである Service/Route 方式を使用してアプリケーションを公開し、クラスター外からアプリケーションに到達できるようにします。これにより、VM 上のアプリケーションを直接公開することで、よりモダンな仮想マシン管理アプローチを提供します。

[[service_route]]
== Service/Route によるアプリケーションの公開

デフォルトでは、仮想マシンは SDN に接続されており、ネットワークの残りの部分へのアクセスを与える便利で簡単な方法です。ただし、仮想マシンや OpenShift クラスター内の他のポッドが仮想化アプリケーションを見つけて接続するのは難しい場合があります。これを解決するため、2 台の Windows ベース Web サーバー間で接続を分散する *Service* を使用し、各サービスディスカバリー用の DNS エントリを作成し、*Route* を作成して外部クライアントが仮想マシン内でホストされているアプリケーションにアクセスできるようにします。

IMPORTANT: モジュール *Migrating Existing Virtual Machines* を完了していない場合は、先にそのモジュールを完了することを推奨します。完了していない場合、または移行プロセスがまだ保留中の場合は、*vmimported-{user}* プロジェクトで利用可能な、事前に準備された仮想マシンを使用できます。これらの事前インポート済み仮想マシンを使用する場合は、以下の例の *vmexamples-{user}* 名前空間をすべて *vmimported-{user}* に置き換えてください。

=== Service の概要

*Service* はトラフィックのソース/ターゲットを識別し、ラベルに基づいてクライアントをエンドポイントに誘導します。現在、VM にはまだラベルが割り当てられていません。

VM を Service に正常に関連付けるには、次を行う必要があります:

* VM にラベルを追加します。両方の Windows IIS サーバーは同じロードバランサーの背後にあるため、同じラベルを使用します。
* Service を作成して、2 台の Windows IIS サーバーをクラスター上の他のワークロードから利用可能にします。OpenShift は Service 名を DNS 名として使用し、ロードバランサーを内部から自動的にアクセス可能にします。
* *Route* を作成して、Service を OpenShift 外から利用可能にします。

まず、OpenShift Virtualization GUI で仮想マシンの定義を変更してラベルを追加します。


=== 仮想マシンへのラベル付け

. 左側列で *VirtualMachines* をクリックし、3 台のインポート済み仮想マシンがまだ実行されていなければ *start* します。右側のツリービューで *Status* 列でソートすれば簡単に確認できます。
+
image::2025_spring/module-08-workingvms/11_Imported_VMs_List.png[link=self, window=blank, width=100%]
+
NOTE: 正しいプロジェクトを選択してください。*Migrating Existing Virtual Machines* モジュールを完了した場合は *vmexamples-{user}*、完了していない場合は *vmimported-{user}* です。

. *winweb01-{user}* VM を選択し、*YAML* タブに移動します。
. *spec:* セクションを見つけ、*template.metadata* の下の *labels* セクションに次を追加します:
+
[source,yaml,role=execute]
----
env: webapp
----
+
IMPORTANT: インデントを下のスクリーンショットとまったく同じにしてください。
+
image::2025_spring/module-08-workingvms/12_Imported_VMs_YAML.png[link=self, window=blank, width=100%]

. VM *winweb02-{user}* についても同じ手順を *繰り返し* ます。
. 設定変更後、*winweb01-{user}* と *winweb02-{user}* の両方の仮想マシンが再起動されていることを確認してください。
+
NOTE: 各 VM のコンソールタブにアクセスして、VM が正常に動作していることを確認してください。

=== Service の作成

. 左側メニューで *Networking* を展開し、*Services* をクリックします。表示された画面で、隅の *Create Service* ボタンをクリックします。
+
image::2025_spring/module-08-workingvms/13_Navigate_Service.png[link=self, window=blank, width=100%]

. YAML を次の定義で置き換えます
+
[source,yaml,role=execute,subs="attributes"]
----
apiVersion: v1
kind: Service
metadata:
  name: webapp
  namespace: vmexamples-{user}
spec:
  selector:
    env: webapp
  ports:
  - protocol: TCP
    port: 80
    targetPort: 80
----
+
IMPORTANT: 仮想マシンがある *namespace*（*vmexamples-{user}* または *vmimported-{user}*）が Service YAML で使用されていることを確認してください。
+
image::2025_spring/module-08-workingvms/14_Service_YAML.png[link=self, window=blank, width=100%]

. 下部の *Create* ボタンをクリックします。YAML が保存されたという通知が表示されます。
. 新しく作成された *webapp* Service の詳細ページから、*Pod selector* リンクを見つけてクリックします。
+
image::2025_spring/module-08-workingvms/15_Imported_VMs_PodSelector.png[link=self, window=blank, width=100%]

. 2 台の Windows VM が Service によって正しく識別され、ターゲットされていることを確認します。
+
image::2025_spring/module-08-workingvms/16_Imported_VMs_Pods.png[link=self, window=blank, width=100%]

=== Route の作成

これで Windows IIS サーバーは OpenShift クラスター内からアクセス可能になりました。他の仮想マシンは、Service 名 + 名前空間で決定される DNS 名 **webapp.vmexamples-{user}** を使用してアクセスできます。ただし、これらの Web サーバーはアプリケーションのフロントエンドであるため、外部からアクセス可能にしたいと考えています。これは *Route* を使用して公開することで行います。

. *Networking* の下で、左ナビゲーションメニューの *Routes* オプションをクリックします。画面中央の *Create Route* ボタンをクリックします。
+
image::2025_spring/module-08-workingvms/17_Route_Navigation.png[link=self, window=blank, width=100%]

. 以下の情報を使用してフォームに入力し、下部までスクロールして完了したら *Create* をクリックします。
+
.. *Name*: *route-webapp*
.. *Service*: *webapp*
.. *Target port*: *80 -> 80 (TCP)*
.. *Secure Route*: *Enabled*
.. *TLS termination*: *Edge*
.. *Insecure traffic*: *Redirect*
+
image::2025_spring/module-08-workingvms/18_Create_Route.png[link=self, window=blank, width=100%]

. *Location* フィールドに表示されているアドレスに移動します
+
image::2025_spring/module-08-workingvms/19_Route_Access.png[link=self, window=blank, width=100%]

. ページが読み込まれるとエラーが表示されます。何か問題があるはずです。これは、Windows Web サーバーが移行後にデータベース VM に接続できないためです。
+
image::2025_spring/module-08-workingvms/20_WebApp_Error.png[link=self, window=blank, width=100%]
+
NOTE: 接続の問題に対処するため、Web サーバーからアクセスできるようにデータベース VM 用の Service を作成する必要があります。

. 再度 *Networking* -> *Services* に移動し、*Create Service* を押します。YAML を次の定義で置き換えます:
+
[source,yaml,role=execute,subs="attributes"]
----
apiVersion: v1
kind: Service
metadata:
  name: database
  namespace: vmexamples-{user}
spec:
  selector:
    vm.kubevirt.io/name: database-{user}
  ports:
  - protocol: TCP
    port: 3306
    targetPort: 3306
----
+
image::2025_spring/module-08-workingvms/21_Database_YAML.png[link=self, window=blank, width=100%]
+
IMPORTANT: 仮想マシンがある名前空間（*vmexamples-{user}* または *vmimported-{user}*）が Service YAML で使用されていることを確認してください。
+
. YAML を貼り付けたら、*Create* ボタンをクリックします。
. ブラウザで webapp URL を再読み込みし、移行済み Web アプリケーションが正常に動作する結果が得られることを確認してください。
+
image::2025_spring/module-08-workingvms/22_WebApp_Success.png[link=self, window=blank, width=100%]

== まとめ

本モジュールでは、Red Hat OpenShift のネイティブ Service と Route 機能を使用してクラスター外からアクセス可能にすることで、VMware vSphere から OpenShift Virtualization 環境に移行した仮想マシンを、よりモダンなアプローチで操作する体験ができました。

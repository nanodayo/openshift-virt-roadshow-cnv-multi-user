= テンプレートと InstanceType の管理

== はじめに

事前設定済みの Red Hat 仮想マシンテンプレートは、左側メニューの *Virtualization* から *Templates* ページに一覧表示されます。これらのテンプレートは、Red Hat Enterprise Linux、Fedora、CentOS、Microsoft Windows Desktop、Microsoft Windows Server の各エディション向けに利用できます。Red Hat 関連の各仮想マシンテンプレートには、オペレーティングシステムイメージ（ブートソース）、OS のデフォルト設定、フレーバー（CPU とメモリ）、ワークロードタイプ（server）が事前設定されています。他の OS 向けテンプレートには OS イメージは含まれませんが、各 OS に推奨される設定が事前構成されています。

*Templates* ページには、4 種類の仮想マシンテンプレートが表示されます。

* *Red Hat Supported* テンプレートは Red Hat による完全サポート対象です。
* *User Supported* テンプレートは、ユーザーがクローンしてカスタマイズした *Red Hat Supported* テンプレートです。
* *Red Hat Provided* テンプレートは Red Hat によるサポートが限定的です。
* *User Provided* テンプレートは、ユーザーがクローンしてカスタマイズした *Red Hat Provided* テンプレートです。

== ラボの準備

. これから行うタスクでは、追加の VM をいくつかプロビジョニングする必要があります。準備として、共有環境にラボを完了するのに十分なリソースを確保するため、既存の *fedora01* および *fedora02* 仮想マシンをシャットダウンしてください。

. 左側メニューから *Virtualization* パースペクティブに移動し、*Virtualmachines* をクリックします。
. VM ワークロードをホストしているアクセス可能な各プロジェクトが、中央列のツリービューに表示されます。（最低限、プロジェクト *vmimported-{user}* と *vmexamples-{user}* を展開して、仮想マシンの状態を確認してください。）
. 状態が *Running* の VM がある場合は、中央のツリー列で VM を選択し、*Actions* ドロップダウンメニューから *Stop* ボタンまたはオプションを選択します。

これですべての VM が *Stopped* 状態になっているはずです。

== Windows VM テンプレートの作成

本ラボのこのセグメントでは、Web サーバーでホストされている ISO を使用して Microsoft Windows Server 2019 をインストールします。これは、Web サーバー、オブジェクトストレージ、クラスター内のその他の永続ボリュームなど、多くの場所からディスクを取得できる機能を活用して、仮想マシンにオペレーティングシステムをインストールする方法の 1 つを示しています。

初期の OS インストール後は、sysprep 済み仮想マシンからクローンしたルートディスクを作成し、他のテンプレートで使用することで、このプロセスを効率化できます。

NOTE: テンプレート OS として使用するゲスト OS の準備手順は OS ごとに異なります。テンプレート OS を準備する際は、組織のガイドラインと要件に必ず従ってください。

. 左メニューから *Catalog* に移動し、上部付近の *Template catalog* タブをクリックします。

. 検索バーに *win* と入力するか、スクロールして *Microsoft Windows Server 2019 VM* タイルを見つけます。
+
image::2025_spring/module-07-tempinst/16_Windows_2k19_Tile.png[link=self, window=blank, width=100%]

. テンプレートに関連するデフォルト設定を示すダイアログが表示されます。
+
NOTE: ブートソースが提供されていないため、最初はこの VM をクイック作成するオプションがないことに注目してください。ニーズに合わせて VM をカスタマイズする必要があります。
+
image::2025_spring/module-07-tempinst/17_Windows_2k19_Dialog.png[link=self, window=blank, width=100%]
+
. このダイアログで:
* 名前 *win-sysprep* を指定
* *Boot from CD* チェックボックスを有効化
* ドロップダウンメニューから *URL (creates PVC)* を選択
* *image URL* を指定: https://catalog-item-assets.s3.us-east-2.amazonaws.com/qcow_images/Windows2019.iso
* CD ディスクサイズを *5 GiB* に縮小
* *Disk source* を *Blank* のまま、サイズをデフォルト値 *60 GiB* に設定
* *Mount Windows drivers disk* チェックボックスが有効になっていることを確認。**VirtIO ドライバーを提供するため、Windows システムのインストールにはこれが必要です。**
+

image::2025_spring/module-07-tempinst/18_Windows_2k19_Parameters.png[link=self, window=blank, width=100%]

[[instance_types]]
== InstanceType の概要

仮想マシンのデプロイプロセスを簡素化するため、OpenShift 4.14 以降、デフォルトの構成メカニズムが *Instance Types* の使用を重視するように変更されました。InstanceType は、新しい VM に適用するリソースと特性を定義できる再利用可能なオブジェクトです。カスタム InstanceType を定義するか、OpenShift Virtualization のインストール時に含まれる各種の InstanceType を使用して VM をプロビジョニングできます。これは、主要なクラウドプロバイダーのセルフサービスカタログを利用する際のユーザー体験に近いものです。

本セクションでは、InstanceType を使用した VM のプロビジョニングを探ります。

. 開始するには、左側メニューで *Catalog* をクリックします。デフォルトのカタログ項目は *InstanceType* です。
+
image::2025_spring/module-07-tempinst/33_Left_Menu_Catalog.png[link=self, window=blank, width=100%]

. InstanceType を使用する最初のステップは、起動元のボリュームを選択することです。ブートソースを提供するテンプレートと同様に、これらのブートソースは InstanceType でプロビジョニングされたゲストで使用できます。*openshift-virtualization-os-images* プロジェクトを選択して含まれるボリュームを確認するか、*Add volume* ボタンで独自のボリュームをアップロードできます。
+
image::2025_spring/module-07-tempinst/34_Volume_Boot.png[link=self, window=blank, width=100%]

. *rhel9* ブートボリュームをクリックして、起動元ボリュームとして選択します。選択すると、イメージ名の左側に小さな縦の青い線が表示され、名前自体が太字になります。
+
image::2025_spring/module-07-tempinst/35_Select_RHEL9.png[link=self, window=blank, width=100%]

. 次に、使用する InstanceType を選択できます。デフォルトで Red Hat 提供の InstanceType があるか、特定のユースケース向けに独自のものを作成できます。提供されている InstanceType にカーソルを合わせると、想定用途の説明が表示されます。
+
image::2025_spring/module-07-tempinst/36_Select_InstanceType.png[link=self, window=blank, width=100%]
+
* Red Hat 提供の InstanceType は次の用途向けです:
** *N series*: VNF などのネットワーク集約型 DPDK ワークロード向けに設計されています。
** *O series*: メモリオーバーコミットが事前設定された特殊な汎用 InstanceType です。
** *CX series*: 追加の機能オフロードのために追加の専用 CPU を要求することで、計算集約型ワークロード向けに設計されています。
** *U series*: 最も汎用的、または「ユニバーサル」な InstanceType です。
** *M series*: メモリ集約型ワークロード向けに設計されています。

. *U series* タイルをクリックすると、汎用 InstanceType の定義済みリソースのドロップダウンリストが表示されます。ここのデフォルトオプションは *medium: 1 CPUs, 4 GiB Memory* です。これを選択します。選択は再び青い線と InstanceType の太字で示されます。
+
image::2025_spring/module-07-tempinst/37_InstanceType_Resources.png[link=self, window=blank, width=100%]

. InstanceType を使用してプロビジョニングする際に完了する必要がある最後のセクションは、テンプレートセクションと同様です。仮想マシンの名前を指定し、バッキングディスクに使用するストレージクラスを選択する必要があります。デフォルトでは VM 用の名前が生成され、デフォルトのストレージクラスが選択されます。問題なければ、*Create VirtualMachine* ボタンをクリックします。
+
image::2025_spring/module-07-tempinst/38_VM_Details.png[link=self, window=blank, width=100%]

. 仮想マシンの概要ページに移動し、InstanceType を使用してプロビジョニングされた VM が起動して実行中であることを確認します。
+
image::2025_spring/module-07-tempinst/39_VM_Overview.png[link=self, window=blank, width=100%]

== クリーンアップ

次のラボのためにリソースを節約するため、このモジュールで作成した VM をすべて停止してください。

. 左側メニューから *Virtualization* パースペクティブに移動し、*Virtualmachines* をクリックします。
. VM ワークロードをホストしているアクセス可能な各プロジェクトが、中央列のツリービューに表示されます。（最低限、プロジェクト *vmimported-{user}* と *vmexamples-{user}* を展開して、仮想マシンの状態を確認してください。）
. 状態が *Running* の VM がある場合は、中央のツリー列で VM を選択し、*Actions* ドロップダウンメニューから *Stop* ボタンまたはオプションを選択します。

これですべての VM が *Stopped* 状態になっているはずです。

== まとめ

本セクションでは、既存のテンプレートをクローンしてカスタマイズし、データベースなど特定のワークロード向けに使用できるテンプレートを作成する方法を学びました。また、ブートソースのない既存の Windows テンプレートの 1 つを設定し、インストールプロセスを自動化して、その VM で作成されたインストール PVC をクローンすることで、今後のデプロイを容易に作成できるようにする方法も学びました。さらに、よりクラウドに近い体験のために、特定のワークロード向けに仮想マシンをさらにカスタマイズする InstanceType の利用方法も紹介しました。

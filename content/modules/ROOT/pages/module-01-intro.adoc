= 仮想マシン管理

== はじめに

このラボの最初のセクションでは、OpenShift Virtualization で VM を作成・管理する基本を学びます。OpenShift 4.18 以降では、新しい *Virtualization* perspective と仮想マシン用のツリービューが追加され、仮想化ベースのアセットをより簡単に可視化・管理できるようになりました。UI の変更を確認した後、Web コンソールが事前定義済みテンプレートから仮想マシンを作成する一連のプロセスをどのように案内するかを見ていきます。次に、その VM のプロパティを確認し、基本的なカスタマイズを行い、仮想マシン管理者によく求められるライブマイグレーションなどのアクションを実行します。

.*目標*

* 新しい仮想マシンを作成する
* 仮想マシンのリソースを確認・変更する
* OpenShift コンソールを使用した VM 電源状態の管理方法を理解する
* 2 台のホスト間で VM をライブマイグレーションする

参考までに、OpenShift Console へのログイン情報は次のとおりです。

OpenShift クラスターコンソールは {openshift_console_url}[こちら^] から利用できます。

. VM を作成する前に、新しいプロジェクトを作成する必要があります。仮想マシンは特定のプロジェクト（namespace）にデプロイされ、デフォルトでは namespace への権限のないユーザーはアクセス、管理、制御できません。管理者はすべてのプロジェクトにアクセスできるため、すべての仮想マシンを表示できますが、一般ユーザーは必要に応じてプロジェクトへのアクセス権を付与される必要があります。
+
. 中央ツリービュー列の右上にある *Create Project* をクリックします。
+
image::2025_spring/module-01-intro/10_Column_Create.png[link=self, window=blank, width=100%]

. *Name* フィールドに *vmexamples-{user}* と入力してプロジェクトに名前を付け、*Create* をクリックします。
+
image::2025_spring/module-01-intro/11_Create_Project.png[link=self, window=blank, width=100%]
+
NOTE: 仮想マシン概要列はすぐにこの新しいプロジェクトを表示するように変更されますが、プロジェクト内に VM がなく、デフォルトで非表示にするオプションがオンになっているため、中央列にはまだ表示されません。

独自環境でデプロイする場合、利用可能なオプションをカスタマイズできるため、これらのブートソースのデフォルトの可用性を変更したり、組織のニーズに合わせたカスタムディスクを作成するためにこれらのソースディスクを削除したりすることを選択できます。

image::2025_spring/module-01-intro/13_Create_VM_Templates.png[link=self, window=blank, width=100%]

. *Fedora VM* タイルを選択すると、ダイアログが開きます。
+
image::2025_spring/module-01-intro/14_Create_VM_Quick.png[link=self, window=blank, width=100%]

. 名前を *fedora01* に変更し、*Quick create VirtualMachine* を押します。

image::2025_spring/module-01-intro/15_Create_VM_Quick_Name.png[link=self, window=blank, width=100%]

. ツリービューに戻り、仮想マシン概要列で新しい VM の情報を確認します。また、VM を含む *vmexamples-{user}* プロジェクトが中央列に表示され、プロジェクト内でハイライトされていることにも注目してください。

注意深く見ると、準備が整うと仮想マシン概要列で VM Status が *Provisioning* から *Starting*、最終的に *Running* に切り替わるのが確認できます。

この間、ストレージプロバイダーはテンプレートディスクをクローンし、新しく作成された仮想マシンで使用できるようにします。所要時間は、ブートディスクの作成に使用されるストレージプロバイダーと、システムへの現在の負荷によって異なります。

* *Utilization*: このタイルには、CPU、Memory、Storage、Network スループットなど、この仮想マシンが現在使用しているリソースの概要が表示されます。
+
image::2025_spring/module-01-intro/17_Fedora_Details.png[link=self, window=blank, width=100%]

+
image::2025_spring/module-01-intro/18_Fedora_Events.png[link=self, window=blank, width=100%]
+
* _DataVolume_ が作成されました。_DataVolumes_ は VM ディスクの作成を管理し、仮想マシンの作成ワークフロー中にクローンまたはインポートプロセスを OpenShift ネイティブストレージ上に抽象化します。
* 新しい _VM instance_ Fedora01 が起動されました。

[[admin_vms]]
== 仮想マシンの管理

仮想マシンの管理と利用は、作成と構成のカスタマイズだけではありません。プラットフォーム管理者として、VM の状態を制御し、ライブマイグレーションをトリガーしてリソースのバランス調整、メンテナンスタスクの実行、ノードの再構成を行える必要もあります。

. *Configuration* タブをクリックします。これは、仮想マシンの詳細情報の取得とリソースの変更への入り口です。
+
image::2025_spring/module-01-intro/19_VM_Configuration.png[link=self, window=blank, width=100%]
+
7 つのサブタブが含まれます。
+
image::2025_spring/module-01-intro/20_Configuration_Tab.png[link=self, window=blank, width=100%]
+
* *Details*: このタブは、VM のすべての物理的な特性を 1 つのパネルに表示します。ここから、CPU やメモリの変更、ホスト名の変更、パススルーデバイスの接続、ブート順序の変更など、さまざまな記述子と基本的なハードウェア構成を編集できます。
* *Storage*: このタブは、システムに接続されたディスクを一覧表示し、新しいディスクを追加できます。ゲストがエージェントで構成されている場合、ファイルシステムと使用率が一覧表示されます。ここでは _ConfigMaps_、_Secrets_、_Service Accounts_ を追加ディスクとして接続できます。これは、仮想マシン内で実行されているアプリケーションに構成データを渡す際に有用です。
* *Network*: このタブは、VM に構成されている現在のネットワークインターフェースを表示し、新しいインターフェースを追加できます。
* *Scheduling*: このタブには、VM を実行する場所と、エビクションに従う戦略を示す高度な構成オプションが含まれます。このタブは（アンチ）アフィニティルールの構成、ノードセレクターと toleration の構成、VM がスケジュールされるクラスターノードに影響するその他の動作を設定するために使用されます。
* *SSH*: このタブでは、構成されたロードバランサー上に SSH サービスを作成するか、機能が有効な場合は公開 SSH キーを注入することで、マシンへのリモートアクセスを構成できます。
* *Initial run*: このタブでは、Linux 向けの _cloud-init_ または Microsoft Windows 向けの _sys-prep_ を構成できます。SSH キーの注入、アプリケーションのインストール、ネットワーク構成など、初回ブート時に実行するコマンドの設定も含まれます。
* *Metadata*: このタブは、仮想マシンに適用されている現在の Labels と Annotations を表示します。これらの値を変更すると、特定の目的でマシンにタグ付けしたり、マシンを一意に識別して自動化ワークフローを有効にしたりするのに役立ちます。

. それぞれをクリックして自由に探索できますが、入門としては、ストレージとネットワークに特に焦点を当てましょう。

. *Storage* タブをクリックして、VM に関連付けられたディスクを一覧表示します。
+
image::2025_spring/module-01-intro/21_Storage_Tab.png[link=self, window=blank, width=100%]
+
この環境では、ディスクに使用されるストレージのソースとタイプを定義するデフォルト StorageClass は *ocs-external-storagecluster-ceph-rbd* です。このストレージは、仮想マシンの実行用に OpenShift Data Foundation（ODF）が提供するデフォルトタイプです。各ストレージプロバイダーには、VM ディスクをバックアップするストレージの特性を定義する異なるストレージクラスがあります。

. *Network* サブタブをクリックして、VM に接続されたネットワークインターフェースを確認します。
+
image::2025_spring/module-01-intro/22_Network_Tab.png[link=self, window=blank, width=100%]
+
VM をクイック作成すると、デフォルトで *Pod Networking* ネットワーク上にタイプ *masquerade* のインターフェースが作成されます。これにより VM が SDN に接続され、OpenShift クラスター外の世界への egress が提供されます。クラスター内の他の VM および Pod は、このインターフェースを使用して仮想マシンにアクセスできます。
+
さらに、SDN に接続された VM は、Route または type load balancer の Service を使用して外部からアクセスでき、Network Attachment Definition または User-defined Network（UDN）で VLAN または外部ネットワークを定義して直接接続することもできます。これらのオプションは、後ほど詳しく探索します。

[[vm_state]]
== 仮想マシン状態の制御

Virtualization 環境の管理権限が付与されたユーザーとして、Web コンソールから仮想マシンの停止、起動、再起動、一時停止、一時停止解除を行えます。

. *Overview* タブをクリックして、概要画面に戻ります。

. 右上隅に、実行状態用のショートカットボタン（stop、restart、pause、start）と、*Actions* というタイトルのドロップダウンメニューがあることに注目してください。
+
image::2025_spring/module-01-intro/23_VM_State_Actions.png[link=self, window=blank, width=100%]
+
* *Stop*: 仮想マシンの正常シャットダウンを開始します。
* *Restart*: オペレーティングシステムに再起動信号を送信します。正常に動作するにはゲスト統合が必要です。
* *Pause*: プロセスは凍結され、CPU リソースと I/O へのさらなるアクセスは停止しますが、ハイパーバイザーレベルで VM が使用するメモリは割り当てられたままです。
* *Start*: 停止中の仮想マシンを起動します。マシンが実行中の場合はグレーアウトされます。

. ショートカットボタンは便利ですが、*Actions* メニューをクリックしてドロップダウンリストで利用可能なオプションを確認することでも、これらのオプションやその他のオプションにアクセスできます。
+
image::2025_spring/module-01-intro/24_VM_Actions_Menu.png[link=self, window=blank, width=100%]

. *Stop* ボタンを押し、仮想マシンが *Stopped* 状態になるまで待ちます。
+
image::2025_spring/module-01-intro/25_VM_Stopped.png[link=self, window=blank, width=100%]

. *Actions* をクリックすると、*Start* オプションが表示され、*Restart* と *Pause* オプションはグレーアウトされます。
+
image::2025_spring/module-01-intro/26_VM_Actions_List_Stopped.png[link=self, window=blank, width=100%]

. *Start* をクリックし、*Running* ステータスになるまで待ちます。

. *Actions* メニューまたはショートカットボタンを使用して *Pause* オプションを押します。仮想マシンの状態は *Paused* に変わります。
+
image::2025_spring/module-01-intro/27_VM_Actions_Paused.png[link=self, window=blank, width=100%]

. *Actions* メニューの *Unpause* オプション、またはショートカットボタンを使用して、仮想マシンの一時停止を解除します。

[[live_migrate]]
== 仮想マシンのライブマイグレーション

このセクションでは、VM をシャットダウンせずに OpenShift ノード間でマイグレーションします。ライブマイグレーションには *ReadWriteMany*（RWX）ストレージが必要です。これにより、VM ディスクをソースノードと宛先ノードの両方に同時にマウントできます。OpenShift Virtualization は、おなじみの他の仮想化ソリューションとは異なり、多くの異なる VM のディスクを保持する各クラスターメンバーにマウントされたモノリシックなデータストアは使用しません。代わりに、各 VM ディスクは独自のボリュームに保存され、必要な場所・必要なときにのみマウントされます。

. 仮想マシンが実行されている物理ノードを確認するには、*Overview* ページの *General* タイル下にある *Pod* 名 _virt-launcher-fedora01-uuid_ をクリックします。
+
image::2025_spring/module-01-intro/28_Pod_Name.png[link=self, window=blank, width=100%]

. Pod の詳細ページが表示されます。*Node* というセクションヘッダーを探し、pod が実行されている worker の名前を確認します。このスクリーンショットでは _worker-cluster-ttgmt-3_ で実行されています。
+
image::2025_spring/module-01-intro/29_Pod_Details_Node.png[link=self, window=blank, width=100%]

. ブラウザの戻るボタンをクリックして *Overview* ページに戻ります。

. *Actions* メニューを使用し、*Migration* -> *Compute* オプションを選択します。
+
image::2025_spring/module-01-intro/30_VM_Dialog_Migrate.png[link=self, window=blank, width=100%]

. 数秒後、VM のステータスは *Migrating* に変わり、進行状況を追跡できます。
+
image::2025_spring/module-01-intro/31_VM_Migrating.png[link=self, window=blank, width=100%]

. マイグレーションが完了すると、VM は *Running* ステータスに戻りますが、新しいノード上で実行されています。確認のため _virt-launcher-fedora01-uuid_ pod 名をクリックしましょう。
+
image::2025_spring/module-01-intro/32_Migrated_Status.png[link=self, window=blank, width=100%]

. 仮想マシンが新しいノード上で実行されていることが確認できます。画像では _worker-cluster-ttgmt-2_ です。ライブマイグレーションプロセスが VM インスタンスを新しい worker ノード上の新しい pod に非破壊的に転送するため、pod 自体も新しい一意 ID を持つ新しい pod に移動しています。
+
image::2025_spring/module-01-intro/33_Pod_Details_Node_Migrated.png[link=self, window=blank, width=100%]

== まとめ

このラボでは、OpenShift Virtualization の Virtualization 管理環境の概要を確認し、テンプレートから仮想マシンをプロビジョニングし、状態管理や物理ホスト間のライブマイグレーションを含む基本的な仮想マシン管理タスクを実行しました。これらのタスクはすべて、プラットフォーム管理者として一般的かつしばしば必要とされる作業であり、OpenShift Virtualization で VM を操作する際に利用できる基本機能に慣れる良い方法です。

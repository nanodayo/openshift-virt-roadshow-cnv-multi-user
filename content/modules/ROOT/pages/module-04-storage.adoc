= ストレージ管理

Red Hat OpenShift は、オンプレミスおよびクラウドプロバイダーの両方向けに、複数種類のストレージをサポートしています。OpenShift Virtualization は、ワークロードが実行されている環境でサポートされている任意の Container Storage Interface（CSI）プロビジョナーを使用できます。

物理ストレージシステムの例には、Dell/EMC、Fujitsu、Hitachi、NetApp、Pure Storage などがあります。

ソフトウェア定義ストレージの例には、IBM Fusion Data Foundation、OpenShift Data Foundation（ODF）、Portworx などがあります。

NOTE: このリストはすべてを網羅したものではありません。サポートされているすべてのストレージソリューションについては、https://catalog.redhat.com/platform/red-hat-openshift/virtualization#virtualization-infrastructure[Red Hat EcoSystem Catalog^] を参照してください。

このワークショップのセクションでは、Persistent Volume Claims（PVC）について学びます。PVC は、プロバイダーからストレージを要求し、VM ディスクを格納するために使用されます。多くのストレージプロバイダーは、デバイスのスナップショットやクローンもサポートしています。CSI ドライバーおよびストレージデバイスでサポートされている機能については、ベンダーに確認してください。

特筆すべき点として、OpenShift Virtualization 固有のストレージプロトコル（NFS、iSCSI、FC など）に関する制限はありません。唯一の要件は、クラスター内での VM のライブマイグレーションをサポートするために必要な *RWX access mode* が利用可能であることです。それ以外では、組織の VM およびアプリケーションのニーズに最も適したストレージを選択すれば問題ありません。

== スナップショットの管理

OpenShift Virtualization は、CSI ストレージプロバイダーのスナップショット機能に依存して、仮想マシンのディスクスナップショットを作成します。スナップショットは、VM が実行中の「オンライン」状態、または VM の電源がオフの「オフライン」状態で取得できます。VM に KVM 統合パッケージ（qemu-tools）がインストールされている場合、ゲストオペレーティングシステムを自動的に quiesce（静止）するオプションも利用できます（quiesce により、ディスクのスナップショットがゲストファイルシステムの一貫した状態を表すようになります。例：バッファがフラッシュされ、ジャーナルが一貫した状態になります）。

ディスクスナップショットは CSI によって抽象化されたストレージ実装に依存するため、パフォーマンスへの影響および使用容量はストレージプロバイダーによって異なります。PVC スナップショットの管理方法と、期待するパフォーマンスへの影響の有無については、ストレージベンダーと協力して確認してください。

IMPORTANT: スナップショット自体は、通常、元の物理ボリュームと同じストレージシステム上にローカル保存されるため、バックアップや災害復旧の機能を提供しません。真の災害に耐えるためには、別の場所に 1 つ以上のコピーを保存する、またはリモートの場所にあるストレージシステムにミラーリングするなど、ストレージシステム自体の障害に備えて、別の方法でデータを保護する必要があります。

VM スナップショット機能により、クラスター管理者およびアプリケーション開発者は次の操作を実行できます。

* 新しいスナップショットの作成
* 特定の VM に関連付けられたすべてのスナップショットの一覧表示
* VM をスナップショットに復元
* 既存の VM スナップショットの削除

=== スナップショットの作成と使用

. *Virtualization* パースペクティブのドロップダウンに戻り、左側メニューから *VirtualMachines* をクリックします。中央の列で *vmexamples-{user}* プロジェクトを展開し、*fedora01* 仮想マシンをハイライトします。
+
image::2025_spring/module-04-storage/03_VM_Overview.png[link=self, window=blank, width=100%]

. 現在、この VM のスナップショットは Overview ページに一覧表示されていないことに注目してください。
+
image::2025_spring/module-04-storage/04_Snapshots_Overview.png[link=self, window=blank, width=100%]

. ページ上部の *Snapshots* タブに移動します。
+
image::2025_spring/module-04-storage/05_Snapshot_Menu.png[link=self, window=blank, width=100%]

. *Take snapshot* を押すと、ダイアログが開きます。
+
image::2025_spring/module-04-storage/06_VM_Snapshot_Dialog.png[link=self, window=blank, width=100%]
+
NOTE: *cloudinitdisk* がスナップショットに含まれないという警告が表示されます。これは想定どおりの動作であり、初期起動用のエフェメラルディスクであるために発生します。

. スナップショットの名前は自動生成されます。*Save* を押し、*status* が *Operation complete* と表示されるまで待ちます。
+
image::2025_spring/module-04-storage/07_VM_Snapshot_Taken.png[link=self, window=blank, width=100%]

. 3 点メニューを押すと、VM が現在実行中であるため *Restore* オプションがグレーアウトされていることが確認できます。
+
image::2025_spring/module-04-storage/08_VM_Restore_Disabled.png[link=self, window=blank, width=100%]

. 次に、*Console* タブに切り替えます。ログインして、VM が起動できなくなるような変更を行います。
+
image::2025_spring/module-04-storage/09_Console_Login.png[link=self, window=blank, width=100%]
+
NOTE: *User name* と *Password* の横にコピーアイコンがあり、*Paste to console* ボタンも利用できるため、ログインプロセスがはるかに簡単になります。

. ログインしたら、次のコマンドを実行します。
+
[source,sh,role=execute]
----
sudo rm -rf /boot/grub2; sudo shutdown -r now
----
+
. 実行すると、仮想マシンは自動的に再起動しますが、正常に起動できなくなります。
+
image::2025_spring/module-04-storage/10_Bootloader_Broken.png[link=self, window=blank, width=100%]
+
IMPORTANT: 前のステップでは、ゲスト内からオペレーティングシステムがシャットダウンされました。ただし、OpenShift Virtualization は、VM をホストする Pod がまだ実行中であるため、デフォルトのポリシーに基づいて自動的に再起動します。この動作は、グローバルに、または VM ごとに変更できます。

. *Actions* ドロップダウンメニュー、または右上隅のショートカットボタンから、VM を *Stop* します。正常なシャットダウンを試みるため、マシンが不安定な状態であることから、このプロセスには時間がかかる場合があります。*Actions* ドロップダウンメニューを再度クリックすると、*Force stop* オプションが表示されます。ラボを続行するために、このオプションを使用してください。

. *Overview* タブをクリックして、VM が停止したことを確認できます。先ほど取得したスナップショットが *Snapshots* タイルに一覧表示されていることも確認できます。
+
image::2025_spring/module-04-storage/11_VM_Stopped_Snapshot.png[link=self, window=blank, width=100%]

. *Snapshots* タイルで、スナップショット横の 3 点メニューをクリックします。VM が停止しているため、*Restore* がグレーアウトされていないことが確認できます。クリックします。
+
image::2025_spring/module-04-storage/12_VM_Restore.png[link=self, window=blank, width=100%]

. 表示されたダイアログで、*Restore* を押します。
+
image::2025_spring/module-04-storage/13_VM_Restore_Dialog.png[link=self, window=blank, width=100%]

. VM が復元されるまで待ちます。プロセスは比較的迅速に完了するはずです。上部の *Snapshots* タブをクリックすると、最後の復元操作の詳細を確認できます。
+
image::2025_spring/module-04-storage/14_VM_Restored.png[link=self, window=blank, width=100%]

. *Overview* タブに戻り、VM を起動します。
+
image::2025_spring/module-04-storage/15_VM_Start.png[link=self, window=blank, width=100%]

. *Console* タブをクリックして、VM が再起動し、OS まで正常に起動したことを確認します。
+
image::2025_spring/module-04-storage/16_VM_Running.png[link=self, window=blank, width=100%]

== 仮想マシンのクローン作成

クローン作成により、ストレージ用に独自のディスクイメージを使用する新しい VM が作成されますが、クローンの構成の大部分および保存されたデータはソース VM と同一です。

. *Overview* 画面に戻り、*Actions* ドロップダウンメニューをクリックして VM をクローンするオプションを確認します。
+
image::2025_spring/module-04-storage/17_Overview_Actions_Clone.png[link=self, window=blank, width=100%]

. *Actions* メニューから *Clone* を押すと、ダイアログが開きます。クローン VM の名前を *fedora02* とし、*Start VirtualMachine on clone* チェックボックスがオフのままであることを確認してから、*Clone* をクリックします。
+
image::2025_spring/module-04-storage/18_VM_Clone_Dialog.png[link=self, window=blank, width=100%]

. 新しい VM が作成され、ディスクがクローンされ、自動的にポータルが新しい VM にリダイレクトされます。*Created* 時刻が非常に最近であることが確認できます。
+
image::2025_spring/module-04-storage/19_VM_Cloned.png[link=self, window=blank, width=100%]
+
IMPORTANT: クローンされた VM はソース VM と同じ ID を持つため、アプリケーションや VM とやり取りする他のクライアントとの競合が発生する可能性があります。外部ネットワークに接続されている VM、または同じプロジェクト内の VM をクローンする際は注意してください。

. 画面上部の *YAML* メニューをクリックすると、VM の名前は *fedora02* ですが、*fedora01* ソース VM から残っているラベルがあり、手動で更新する必要があることがわかります。
+
image::2025_spring/module-04-storage/20_Cloned_VM_YAML.png[link=self, window=blank, width=100%]

. YAML の *app* および *kubevirt.io/domain* の値を *fedora02* に設定するよう変更し、下部の *Save* ボタンをクリックします。*fedora02* が新しいバージョンに更新されたというプロンプトが表示されます。これを今行うことで、後続のモジュールでこの VM を扱う際の問題を回避できます。
+
image::2025_spring/module-04-storage/21_Cloned_VM_YAML_Saved.png[link=self, window=blank, width=100%]

. 仮想マシンの YAML の変更が完了したら、*fedora01* と *fedora02* の両方が実行中になるよう起動してください。
+
image::2025_spring/module-04-storage/22_Fedora02_Running.png[link=self, window=blank, width=100%]

== まとめ

このラボのセクションでは、仮想マシンを管理する際に利用可能なストレージオプションを確認しました。また、仮想マシンにプロビジョニングされたストレージに依存する複数の VM 管理機能も実行しました。具体的には、基本的な復元のために VM のスナップショットを取得すること、および他のプロジェクトで使用したり今後の開発を効率化するために VM をクローンすることです。

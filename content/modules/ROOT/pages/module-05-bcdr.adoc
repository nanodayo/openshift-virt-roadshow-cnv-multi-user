= 仮想マシンのバックアップとリカバリ

== はじめに

データ保護は、あらゆるエンタープライズワークロードにおいて重要な話題であり、OpenShift Virtualization で仮想マシンをバックアップおよびリカバリするための選択肢は現在数多く存在します。これらのソリューションの多くは、OpenShift で Pod を保護するのと同様の方法で機能します。仮想マシン、または複数の仮想マシンを含む namespace のバックアップを取得し、リモートのオブジェクトストレージバケットに保存します。これらのバックアップには通常、仮想マシンを定義するメタデータおよびカスタムリソースとともに、永続ストレージボリュームも含まれます。

Red Hat ソリューション:

* https://docs.redhat.com/en/documentation/openshift_container_platform/4.18/html/backup_and_restore/oadp-application-backup-and-restore[*OpenShift APIs for Data Protection (OADP)*^]: 仮想マシンを含む OpenShift オブジェクトのバックアップおよび復元に、ストレージに依存しない方法を提供する Red Hat Operator です。
* https://docs.redhat.com/en/documentation/red_hat_openshift_data_foundation/4.18/html/configuring_openshift_data_foundation_disaster_recovery_for_openshift_workloads/metro-dr-solution[*OpenShift Data Foundation Metro-DR*^] および https://docs.redhat.com/en/documentation/red_hat_openshift_data_foundation/4.18/html/configuring_openshift_data_foundation_disaster_recovery_for_openshift_workloads/rdr-solution[*OpenShift Data Foundation Regional-DR*^]

エコシステムパートナーソリューション:

* https://www.cohesity.com/press/cohesity-enhances-data-protection-and-cyber-resilience-for-red-hat-openshift-virtualization-workloads/[*Cohesity DataProtect*^]
* https://docs.netapp.com/us-en/trident/index.html[*NetApp Trident Protect*^]
* https://portworx.com/blog/disaster-recovery-for-red-hat-openshift-virtualization/[*Portworx Disaster Recovery for OpenShift Virtualization*^]
* https://www.rubrik.com/solutions/openshift[*Rubrik for OpenShift*^]
* https://storware.eu/solutions/virtual-machine-backup-and-recovery/openshift-virtualization-and-kubevirt/[*Storware Backup and Recovery*^]
* https://docs.trilio.io/kubernetes/appendix/backup-and-restore-virtual-machine-running-on-openshift-virtualization[*Trilio for Kubernetes*^]
* https://docs.kasten.io/latest/usage/openshift_virtualization.html[*VEEAM Kasten*^]

NOTE: これは、サポートされているバックアップおよびリカバリソリューションを提供するパートナーの網羅的なリストを意図したものではありません。ストレージまたはデータ保護ベンダーに問い合わせて、製品と OpenShift Virtualization の互換性を確認するか、追加情報については https://catalog.redhat.com/platform/red-hat-openshift/virtualization#virtualization-infrastructure[Red Hat EcoSystem Catalog^] を参照してください。

このラボのセクションでは、OADP を使用して仮想マシンのバックアップおよび復元操作を実行します。

[[review_operator]]
== OADP Operator の確認

. Administrator パースペクティブに再度移動し、左側メニューから *Operators*、続いて *Installed Operators* をクリックします。*oadp-{user}* プロジェクトが選択されていることを確認してください。
+
image::2025_summer/module-05-bcdr/00_Left_Menu.png[link=self, window=blank, width=100%]

. Operator をクリックして詳細を確認します。

. 利用可能な *Provided APIs* を確認します。このモジュールでは、*Backup* および *Restore* 機能を使用します。
+
image::2025_summer/module-05-bcdr/01_Overview.png[link=self, window=blank, width=100%]

. 上部の水平スクロールバーを使用して *DataProtectionApplication* タブに移動します。このオブジェクトは、デプロイされた OADP インスタンスの構成を表します。
+
image::2025_summer/module-05-bcdr/02_DPA.png[link=self, window=blank, width=100%]

. *oadp-dpa* をクリックして _DataProtectionApplication_ の詳細を確認し、上部の *YAML* ボタンをクリックして構成を確認します。
+
image::2025_spring/module-05-bcdr/03_OADP_YAML.png[link=self, window=blank, width=100%]
+
*OADP* には *kubevirt* プラグインが追加されて構成されており、クラスター上で実行されている OpenShift Data Foundation が提供する内部オブジェクトストレージバケットを使用するように設定されていることに注目してください。
+
IMPORTANT: 利便性のため、このラボではローカルのオブジェクトバケットへのバックアップが設定されていますが、本番環境では、局所的な災害からワークロードを保護するため、バックアップ先を外部ストレージシステムまたはクラウドベースのオブジェクトストレージバケットに向ける必要があります。

[[create_backup]]
== 仮想マシンバックアップの作成

前のセクションで作成した VM *fedora02* のバックアップを実行します。バックアップ対象オブジェクトの選択は、ラベル *app* および *vm.kubevirt.io/name* によって定義されます。これには、VM 定義、ディスク、および ConfigMap や Secret など仮想マシンで使用されている追加オブジェクトが含まれます。

NOTE: 前のセクションを完了していない場合、または *fedora02* VM が存在しない場合は、上記の YAML のラベルセレクターを、インベントリ内の仮想マシンに合わせて変更してください。

. *Operator details* に戻り、水平スクロールバーを使用して *Backup* タブが表示されるまでスクロールします。

. *Backup* タブをクリックし、*Create Backup* ボタンを押します。
+
image::2025_summer/module-05-bcdr/04_Backup_Tab.png[link=self, window=blank, width=100%]

. _YAML view_ に切り替え、デフォルトの内容を以下の内容に置き換えます。
+
[source,yaml,role=execute,subs="attributes"]
----
---
apiVersion: velero.io/v1
kind: Backup
metadata:
  name: backup-fedora02
  namespace: oadp-{user}
  labels:
    velero.io/storage-location: default
spec:
  defaultVolumesToFsBackup: false
  orLabelSelectors:
  - matchLabels:
      app: fedora02
  - matchLabels:
      vm.kubevirt.io/name: fedora02
  csiSnapshotTimeout: 10m0s
  ttl: 720h0m0s
  itemOperationTimeout: 4h0m0s
  storageLocation: oadp-dpa-1
  hooks: {}
  includedNamespaces:
  - vmexamples-{user}
  snapshotMoveData: false
----

. 下部の *Create* ボタンをクリックします。
+
この YAML の内容は、namespace *vmexamples-{user}* 内でラベル *app: fedora02* を持つすべてのオブジェクトが、*DataProtectionApplication* 構成で指定された場所にバックアップされることを示しています。
+
image::2025_spring/module-05-bcdr/05_Create_Backup_YAML.png[link=self, window=blank, width=100%]

. *Status* 列が *Completed* に変わるまで待ちます。これは、仮想マシンが正常にバックアップされたことを示します。
+
image::2025_summer/module-05-bcdr/06_Backup_Completed.png[link=self, window=blank, width=100%]

[[restore_backup]]
== バックアップからの復元

. 左側メニューから *Virtualization*、続いて *VirtualMachines* をクリックします。中央のツリー列で *vmexamples-{user}* プロジェクトを展開し、*fedora02* VM をクリックします。
+
image::2025_spring/module-05-bcdr/07_Fedora02_Overview.png[link=self, window=blank, width=100%]

. 仮想マシンを停止し、停止したら *Actions* ドロップダウンをクリックして VM を *Delete* するオプションを選択します。
+
image::2025_spring/module-05-bcdr/08_Delete_VM.png[link=self, window=blank, width=100%]

. プロンプトが表示されたら、赤い *Delete* ボタンをクリックして仮想マシンの削除を確認します。
+
image::2025_spring/module-05-bcdr/09_Confirm_Delete.png[link=self, window=blank, width=100%]

. 仮想マシンがインベントリから消えます。
+
image::2025_spring/module-05-bcdr/10_Deleted_VM.png[link=self, window=blank, width=100%]

. *Operators*、続いて *Installed Operators* をクリックし、再度 *OADP Operator* を選択します。（*OADP-{user}* プロジェクトに戻す必要がある場合があります。）

. 水平ナビゲーションバーで *Restore* タブを見つけ、*Restore* タブをクリックしてから *Create Restore* を押します。
+
image::2025_summer/module-05-bcdr/11_Restore_Tab.png[link=self, window=blank, width=100%]

. YAML view に切り替え、内容を以下の内容に置き換えます。
+
[source,yaml,role=execute,subs="attributes"]
----
---
apiVersion: velero.io/v1
kind: Restore
metadata:
  name: restore-fedora02
  namespace: oadp-{user}
spec:
  backupName: backup-fedora02
  includedResources: []
  excludedResources:
  - nodes
  - events
  - events.events.k8s.io
  - backups.velero.io
  - restores.velero.io
  restorePVs: true
----

. 下部の *Create* ボタンを押します。
+
image::2025_spring/module-05-bcdr/12_Create_Restore_YAML.png[link=self, window=blank, width=100%]

. *Status* 列が *Completed* に変わるまで待ちます。
+
image::2025_summer/module-05-bcdr/13_Restore_Completed.png[link=self, window=blank, width=100%]

. *Virtualization* に戻り、左側メニューから *Virtual Machines* をクリックし、*fedora02* 仮想マシンが復元されたことを確認します（*vmexamples-{user}* プロジェクト内）。*Created* の値がかなり最近であることが確認できるはずです。
+
image::2025_spring/module-05-bcdr/14_VM_Restored.png[link=self, window=blank, width=100%]

== まとめ

仮想マシンの保護は、仮想化プラットフォームの重要な側面です。OpenShift Virtualization は、OADP の使用などネイティブな保護を可能にする複数の方法、またはストレージおよびバックアップパートナーが自社のソリューションを統合できるようにする方法を提供します。仮想マシンの保護方法について質問がある場合は、ワークショップのプロクターに遠慮なくお尋ねいただくか、ベンダーに問い合わせて OpenShift Virtualization との互換性を確認してください。

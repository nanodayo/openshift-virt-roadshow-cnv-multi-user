= 既存仮想マシンの移行

== はじめに

このラボでは、https://docs.redhat.com/en/documentation/migration_toolkit_for_virtualization/2.8/[Migration Toolkit for Virtualization^] (MTV) を使用して、VMware vSphere から OpenShift へ仮想マシンをインポートします。移行ツールキットは、次の 2 つのインポート「モード」をサポートしています。

* Cold migration（コールド移行）は、移行を開始する前にソース仮想マシンの電源を切ります。これがデフォルトの移行タイプです。
* Warm migration（ウォーム移行）は、ソース仮想マシンが稼働したままデータをコピーします。データの大部分が移行されると、VM はシャットダウンされ、最終的なデータが宛先にコピーされます。その後、新しい VM を起動できるため、VM 上のアプリケーションのダウンタイムを大幅に短縮できます。

NOTE: 移行ツールキットは、OperatorHub で利用可能な Operator を使用して、すでにクラスターにデプロイされています。

Operator のインストールと構成方法に関するドキュメントは、https://docs.redhat.com/en/documentation/migration_toolkit_for_virtualization/2.8/html/installing_and_using_the_migration_toolkit_for_virtualization/installing-the-operator_mtv[こちら^]で確認できます。

Migration Toolkit for Virtualization を独自の要件に合わせて構成する方法の詳細については、次のリンクのドキュメントを参照してください。

* https://docs.redhat.com/en/documentation/migration_toolkit_for_virtualization/2.8/html/installing_and_using_the_migration_toolkit_for_virtualization/prerequisites_mtv#openstack-prerequisites_mtv[OpenStack^]
* https://docs.redhat.com/en/documentation/migration_toolkit_for_virtualization/2.8/html/installing_and_using_the_migration_toolkit_for_virtualization/prerequisites_mtv#rhv-prerequisites_mtv[Red Hat Virtualization^]
* https://docs.redhat.com/en/documentation/migration_toolkit_for_virtualization/2.8/html/installing_and_using_the_migration_toolkit_for_virtualization/prerequisites_mtv#vmware-prerequisites_mtv[VMware vSphere^]

.*目標*

* VMware vSphere 環境を確認する
* Migration Toolkit for Virtualization (MTV) の構成を確認する
* Migration Plan を作成する
* VM を OpenShift Virtualization に移行する
* 埋め込みインタラクティブデモで高度なオプションを確認する

[[prerequisites]]
== 移行の前提条件

すべての移行に次の前提条件が適用されます。

* ISO イメージおよび CD-ROM ディスクはアンマウントされている必要があります。
* 各 NIC には IPv4 アドレスまたは IPv6 アドレスのいずれかが含まれている必要がありますが、NIC は両方を使用しても構いません。
* VM のオペレーティングシステムは、OpenShift Virtualization のゲスト OS として https://access.redhat.com/articles/4234591[認定およびサポート対象^]である必要があります。
* VM 名は、小文字 (a-z)、数字 (0-9)、ハイフン (-) のみを使用し、最大 253 文字までです。先頭と末尾の文字は英数字である必要があります。大文字、スペース、ピリオド (.)、特殊文字を含めてはなりません。
* VM 名は、OpenShift Virtualization 環境内の既存 VM の名前と重複してはなりません。

NOTE: *Migration Toolkit for Virtualization* は、ルールに準拠しない VM に新しい名前を自動的に割り当てます。これにより、問題なく移行を続行できます。

[[migrating_vms]]
== VMware からの仮想マシンの移行

3 層アプリケーションが VMware 上にデプロイされており、OpenShift へ移行する対象となっています。

このアプリケーションは、次の 4 つの仮想マシンで構成されています。

* トラフィックを Web サーバーへ転送する HAproxy システム
* MariaDB データベースを実行する Linux システム
* データベースに接続する PHP アプリケーションを IIS でホストする 2 台の Microsoft Windows サーバー

このラボでは、4 台のうち 3 台の仮想マシンを cold migration を使用して移行します。

NOTE: OpenShift は、*Service* を使用して SDN に接続された VM のネットワークトラフィックとロードバランシングをネイティブに処理するため、HAproxy（ロードバランサー）VM を移行する必要はありません。

== 高度な機能のインタラクティブデモ

ラボの cold migration が完了し、これらの仮想マシンで作業できるようになるのを待つ間、Migration Toolkit for Virtualization で実行できる追加の高度な移行オプションをいくつか紹介します。このセクションでは、移行プロセス中の仮想マシンの自動再構成と、移行操作時のダウンタイムを短縮する warm migration の実行方法を説明します。

次のセクションを確認し、インタラクティブデモビデオをお楽しみください。

=== Automated Config Hooks

Automated configuration hooks は、Migration Toolkit for Virtualization に組み込まれた非常に優れた強力な機能です。

Configuration hooks は、Migration Toolkit for Virtualization の機能として含まれています。pre-configuration hook または post-configuration hook として設定でき、移行プロセスの前または後に仮想マシンのプロパティを変更できます。YAML 形式の playbook を通じて Ansible 自動化の力を活用して目的のアクションを実行しますが、https://www.redhat.com/en/hybrid-cloud-solutions/automation?sc_cid=RHCTN0250000435827&gad_source=1&gad_campaignid=20322566154&gbraid=0AAAAADsbVMRTUlnZMtmJPEadK_tiBW92m&gclid=EAIaIQobChMIqt2m1oHxjAMVjnFHAR1rXhMLEAAYASAAEgIdAfD_BwE&gclsrc=aw.ds[Ansible Automation Platform^] の別途サブスクリプションは不要です。代わりに、移行プロセス中に提供された playbook をターゲット仮想マシンに対して実行する別の *ansible-runner* pod 内で実行されます。

これらの自動化タスクは、ソースハイパーバイザー上で動作していた仮想マシンが OpenShift Virtualization 上で期待どおりに動作することを保証するうえで非常に有用です。

ゲスト上のファイルを編集するような単純なタスクから、ハードウェアデバイスの構成を更新するような複雑なタスクまで実行できます。

以下のインタラクティブデモで、両方の例が実際にどのように動作するかを確認してください。

.デモの手順は次のとおりです:
* リモート ESXi ホスト上の仮想マシンを検出し、cold migration プランを構成します。
* pre-migration hook を使用して、ネットワークアダプターを VMware ネイティブ形式から OpenShift Virtualization 用の VirtIO 形式に再構成し、移行プロセスの開始時刻を記録するテキストファイルを書き込みます。
* post-migration hook を使用して、ネットワークアダプターの構成をクリーンアップし、移行プロセスの完了時刻を記録する別のテキストファイルを書き込みます。
* 実行中の仮想マシンが正常に移行され、起動後も変更が保持されていることを確認します。

=== Warm Migration

Migration Toolkit for Virtualization のデフォルトの移行タイプは cold migration です。これは、移行ウィンドウ全体を通じてソース仮想マシンの電源を切った状態にする必要があります。長期間のダウンタイムを許容できない重要なワークロードを抱える組織も多くあります。このようなワークロード向けに、Migration Toolkit for Virtualization は warm migration もサポートしています。

warm migration プロセスは、ソースハイパーバイザー上の Changed Block Tracking (CBT) テクノロジーを活用して実現されます。CBT は、バックアップやディザスタリカバリ操作で、操作中に転送するデータ量を削減するためによく使用されます。仮想マシンで CBT が有効になると、VM ディスク上の変更を記録するために、定期的にゲストのスナップショットが取得されます。VM を移行する際、ゲストがまだ実行中のうちに初期コピーが転送されます。これにより、マシンが稼働中でダウンタイムなしに大量のデータを転送できます。停止時間のウィンドウを確保できると、Migration Toolkit for Virtualization がカットオーバーをトリガーし、ゲストの電源を切って変更された CBT スナップショットデータを転送します。これにより、VM のダウンタイムははるかに短くなります。

.デモの手順は次のとおりです:
* ソースハイパーバイザー上で実行中の Windows および Linux 仮想マシンを確認します。
* 構成済みの Migration Toolkit for Virtualization プロバイダーを確認します。
* カットオーバーフェーズで停止する warm migration プランを作成して実行します。
* ゲストがまだ実行中であることを確認した後、カットオーバー操作を開始します。
* 移行プランが完了した後の環境を確認します。

== 概要

このセクションでは、Migration Toolkit for Virtualization を確認し、VMware vSphere 環境から OpenShift Virtualization への既存仮想マシンの移行を支援するために使用しました。また、特定の移行シナリオで利用できる高度な機能を示すインタラクティブビデオも視聴しました。

Migration Toolkit for Virtualization に加えて、現在利用可能な移行ツールキットが他に 2 つあります。これらを組み合わせることで、組織の要件に応じて、さまざまなタイプのワークロードを OpenShift クラスター内外へ移行できます。

* https://docs.redhat.com/en/documentation/migration_toolkit_for_applications/7.2/html/introduction_to_the_migration_toolkit_for_applications/index[Migration Toolkit for Applications^] - 大規模なアプリケーション近代化をコンテナおよび Kubernetes へ加速します。
* https://https://docs.redhat.com/en/documentation/openshift_container_platform/4.18/html/migration_toolkit_for_containers/about-mtc[Migration Toolkit for Containers^] - OpenShift クラスター間でステートフルなアプリケーションワークロードを移行します。

これらの他の移行ツールキットの詳細については、Red Hat アカウントチームにお問い合わせください。
